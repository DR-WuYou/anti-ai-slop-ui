# 100 分人工打分卡

脚本只能抓表症（`scripts/audit.mjs`）。真验收要坐下来数 10 分钟。每一项按下表给分，最后加总。

## A. 结构（15）

- [ ] 一句话说得清这页是给谁、做什么（3）
- [ ] 有一个明确的视觉重心，其余元素都为它让路（4）
- [ ] 分组靠距离而不是靠盒子，组内 : 组间 ≥ 1:3（4）
- [ ] 没有"四宫格功能卡 + 三 KPI"这类模板句法（4）

## B. 层级（10）

- [ ] 去掉颜色后仍能一眼分出主次（4）
- [ ] 全页只用 2 条对齐线（3）
- [ ] 同一层级只有一种表达方式（描边或阴影或底色，三选一）（3）

## C. 圆角与几何（10）

- [ ] 圆角 ≤4 档，且与元素大小正相关（4）
- [ ] 内层圆角按 `outer − padding` 退让，无同心错误（4）
- [ ] 细分隔线是 0.5px 或半透明，宽度统一（2）

## D. 排版（15）

- [ ] 字号 ≤4 级，比例在 1.2–1.33（4）
- [ ] 行高：正文 1.6–1.75，标题 1.2–1.3（3）
- [ ] 行宽 60–75 字符（3）
- [ ] 中文字体栈西文在前、中文在后、兜底齐全（3）
- [ ] 无全大写眉标、无中文 letter-spacing、标点统一（2）

## E. 颜色（15）

- [ ] 背景只有中性色，颜色留给内容与状态（5）
- [ ] 一个强调色，出现次数可数（4）
- [ ] 正文对比度 ≥4.5:1（4）
- [ ] 没有紫→粉 / 蓝→紫渐变、没有渐变文字（2）

## F. 间距与布局（10）

- [ ] 间距全部落在 4/8 栅格（3）
- [ ] 页边距、区块间距成体系，不靠眼估（3）
- [ ] 移动端触控目标 ≥44px，按钮不挤（2）
- [ ] 长内容不溢出、不截断关键信息（2）

## G. 文案（10）

- [ ] 标题说人话，没有"赋能 / 无缝 / 重新定义"（4）
- [ ] 按钮带宾语，说明具体动作（3）
- [ ] 空状态 / 错误态给出下一步（3）

## H. 动效与状态（10）

- [ ] 时长 120–240ms，曲线统一（3）
- [ ] 只动 transform / opacity，无 `transition: all`（3）
- [ ] hover / focus-visible / active / disabled 四态齐全（3）
- [ ] 尊重 `prefers-reduced-motion`（1）

## I. 无障碍（5）

- [ ] 图标按钮有可读名称（2）
- [ ] 焦点可见，键盘可走完主流程（2）
- [ ] 状态不只靠颜色传达（1）

## 分档

| 分数 | 结论 |
| --- | --- |
| 92–100 | 可以发布，剩下的是风格问题 |
| 85–91 | 合格，挑 3 处最丑的继续修 |
| 70–84 | 骨架没问题，皮肤还在用默认值 |
| <70 | 回第一步：定主体、定 token，重来 |

## 10 分钟评审流程

1. 缩到 30% 看整体：第一眼落在哪？没有落点 → A/B 扣分。
2. 遮住颜色看层级：层级塌了 → B 扣分。
3. 放大到一个圆角：拿标尺量内外弧是否同心 → C。
4. 数一遍字号：超过 5 个 → D 直接不及格。
5. 用取色器抽 10 个颜色：出现紫色渐变 → E 不及格。
6. 滚一遍看间距：随机挑 3 个间距，看是否落在栅格 → F。
7. 遮住图标只看文案：还能看懂吗 → G。
8. 键盘 Tab 走一遍：焦点在哪 → H/I。
