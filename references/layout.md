# 布局与节奏

## 1. 分组的唯一依据：接近原则

距离近的属于一组，距离远的分属不同组。AI 生成页面最常见的错误是"所有间距都差不多"，于是分组失效。

```
标题 → 8px → 副标题      （同一组）
副标题 → 40px → 正文区块   （不同组，差距 5 倍）
```

硬指标：**组内间距 : 组间间距 ≥ 1 : 3**。

## 2. 密度三档

| 档位 | 行高 | 内边距 | 适合 |
| --- | --- | --- | --- |
| 紧凑 | 32–36 | 8–12 | 表格、后台列表、高频操作 |
| 标准 | 40–48 | 12–16 | 表单、卡片、设置页 |
| 宽松 | 56–72 | 20–28 | 营销页、空状态、引导 |

同一个界面里最多两档，切换要有理由（例如列表紧凑、详情宽松）。

## 3. 页面骨架

```css
.page {
  max-width: 1200px;
  margin-inline: auto;
  padding-inline: clamp(16px, 4vw, 32px);
}
.prose { max-width: 68ch; }
```

- 主内容 1120–1280，长文 640–760，两者不要混用同一套栅格。
- 侧栏固定 240–280，主区自适应；别用百分比五五分。
- 首屏高度不要写死 `100vh`：移动端地址栏会吃掉一截，用 `100dvh` 或 `min-height`。

## 4. 对齐

- 一屏最多两条对齐线（左边缘、栅格列）。
- 图标列固定宽度，文字列从同一 x 开始；不要靠 `padding-left` 逐个凑。
- 数字列右对齐、表头与数据同向。
- 卡片内的按钮贴底对齐用 flex + `margin-top: auto`，不要用固定高度硬撑。

## 5. 响应式断点

```css
/* 移动优先 */
/* base: < 640    单列 */
@media (min-width: 768px)  { /* 平板：2 列 */ }
@media (min-width: 1024px) { /* 桌面：主侧栏 */ }
@media (min-width: 1280px) { /* 宽屏：内容居中，不加宽 */ }
```

- 断点按内容需要定，不按设备型号。
- 宽屏不要无限拉宽：加 `max-width` 比加断点更有效。
- 移动端触控目标 ≥ 44×44，间距 ≥ 8。

## 6. 信息层级清单

排完版按顺序检查：

1. 一眼看到的是什么？（只有一个答案才算过）
2. 第二眼看到什么？
3. 第三次点击会去哪？
4. 把颜色去掉，层级还在吗？
5. 把字号缩小 30%，还看得懂吗？

## 7. 常见排版事故

- 卡片网格最后一行只有 1 个，左右不对称 → 调整列数或用 `grid-template-columns: repeat(auto-fit, minmax(240px, 1fr))`。
- 长标题把按钮挤出行 → 标题 `text-wrap: balance` + 按钮 `flex-shrink: 0`。
- 表格横向溢出页面 → 外层 `overflow-x: auto`，不要压缩列宽到不可读。
- 弹层宽度写死 600px，移动端溢出 → `width: min(600px, calc(100vw - 32px))`。
